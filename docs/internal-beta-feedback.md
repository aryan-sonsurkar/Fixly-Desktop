## Section C — Severity Guide

Use these definitions when assigning severity to each bug.

| Level | Label | Definition | Examples |
|-------|-------|------------|----------|
| **P0** | Blocks use | App crashes, data loss, security vulnerability | App crashes on launch, password stored in plaintext, database corruption |
| **P1** | Serious | Feature completely broken or wrong data shown | AI returns wrong answer with confidence, search returns irrelevant results, sync fails silently |
| **P2** | Annoying | Confusing UX, slow response, unclear error message | Button does nothing, error toast disappears too fast, loading spinner with no feedback |
| **P3** | Polish | Typo, visual inconsistency, minor inconvenience | Misaligned text, inconsistent spacing, tooltip with wrong wording |

**Rule of thumb:** If a non-technical user would give up and close the app, it is P0 or P1. If they would frown and keep going, it is P2. If they would never notice, it is P3.
